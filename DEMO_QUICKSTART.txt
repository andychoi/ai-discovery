USAGE OPTIONS

Full Discovery (default)
  $ ./demo.sh
  Time: 2-3 hours
  Output: All docs + mining + self-review

Skip Mining (faster)
  $ ./demo.sh --no-mining
  Time: 1.5-2 hours
  Output: All docs except mining_reports/

Skip Self-Review (quick)
  $ ./demo.sh --quick
  Time: 30-45 minutes
  Output: Docs without claim verification

Force Rescan
  $ ./demo.sh --rescan
  Time: 2-3 hours
  Output: Re-analyzes (ignores cache)

Show Help
  $ ./demo.sh --help

PIPELINE BREAKDOWN

Parsing & Graph         (10-15m)  Parse code, build call graph
  ↓
Tier 1 Summarization    (10-20m)  Summarize code chunks (2B model)
  ↓
Tier 2 Flow Analysis    (15-30m)  Infer business flows (4B model)
  ↓
Scenario Inference      (5-10m)   Extract process flows
  ↓
BPMN Generation         (5-10m)   Create diagrams, PlantUML, Mermaid
  ↓
Process Mining [OPT]    (10-20m)  Conformance analysis, bottlenecks
  ↓
Markdown Rendering      (5m)      Write documentation
  ↓
Self-Review [OPT]       (30-60m)  Verify claims against source code
  ↓
Complete: 2-3 hours total

CONFIGURATION

Models:
  Tier 1 (fast):     Qwen3.5-2B-4bit      (summarization)
  Tier 2 (standard): Qwen3.5-4B-MLX-4bit (flow analysis)
  Tier 3 (dev):      Qwen3.5-9B-MLX-4bit (doc generation)

Server:
  http://localhost:11435 (mlc-server/ollama)

Config File:
  data/todoapp/discovery.yaml

To Enable Process Mining:
  Edit discovery.yaml:
    process_mining:
      enabled: true  # ← Change from false

  Then rerun: ./demo.sh --rescan

TROUBLESHOOTING

"MLC Server is not responding"
  → Start: ollama serve mlx-community/Qwen3.5-2B-4bit
  → Check: curl http://localhost:11435/v1/models

"CUDA out of memory"
  → Reduce model sizes in discovery.yaml
  → Or reduce max_concurrent from 4 to 2

"Discovery takes too long"
  → Run: ./demo.sh --no-mining
  → Or:  ./demo.sh --quick
  → Or both: ./demo.sh --no-mining --quick

"Want to resume"
  → Run: ./demo.sh (auto-resumes from checkpoint)
  → Or: ./demo.sh --rescan (force full rescan)
