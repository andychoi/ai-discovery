# Design: Graph Accuracy for Target Stacks

- **Status:** Accepted (edge-contract parts are Proposed until M1.12; see ADR-0004)
- **Last updated:** 2026-10-08
- **Related items:** M0.3, M0.4, M1.12, M6.1–M6.13
- **Inputs:** `../research/edge-case-catalog.md`, `../research/ai-discovery-audit.md`, `../adr/0004-edge-origin-vocabulary.md`

Every downstream artifact depends on this graph: wiki pages, MCP impact answers, flows and screen specs. The principle, learned from repowise's changelog, is that **a missing edge is recoverable but a confident wrong edge poisons everything after it.** We refuse to guess, we label every guess we do make, and we measure both precision and recall (`benchmark-protocol.md`).

Clean-room rule (ADR-0006): repowise approaches are described in prose in the catalog. Do not open or copy repowise source while implementing.

## 1. File discovery: Walker v2 (M6.1)

**Today.** `src/ai_discovery/repo/lang_detector.py:7-20` and `src/ai_discovery/repo/file_walker.py:58-69` have these problems:
- They skip *any* directory named `packages`, `migrations`, `assets`, `bin`, `out`, `env`, `build` or `vendor`, which loses JS monorepo packages.
- They do not read `.gitignore` (the test name `test_file_walker_respects_gitignore` is misleading).
- They have no size cap and no symlink-cycle guard.
- They do not handle submodules.

**Target.** A single module, `src/ai_discovery/repo/walker.py` (new), replaces both:

| Rule | Behaviour |
|---|---|
| Source of truth | In a git repo, use `git ls-files -co --exclude-standard` (tracked + untracked-not-ignored). Otherwise use pathspec over `.gitignore` files. Honour a `.discoveryignore` file (new). |
| Excludes | Path *patterns* (e.g. `**/node_modules/**`, `**/bin/Debug/**`), not bare directory names. Users can add more in config (`scan.exclude`). |
| Size cap | Two ceilings: `scan.max_file_kb_other` (500) for non-parseable files and `scan.max_file_kb_source` (2048) for parsed source. Skipped files are recorded with kind `file_too_large` in `degradations` (M1.5). |
| Minified / generated | `*.min.js`, plus a long-line sniff on the first 256 KB. Generated-code banners (`@generated`, `<auto-generated>`) and suffixes (`*.designer.cs`, `*.g.cs`, `*.Designer.vb`) are tagged `generated=true`. Generated files are still parsed (WebForms designer files declare controls) but excluded from prose and dead-code-like claims. |
| Binary | A NUL byte in the first 8 KB means binary, **unless** a UTF-16 BOM is present. UTF-16 then goes to the encoding fallback instead of being skipped. |
| Symlinks | Never followed. Targets that resolve inside the tree are pruned to avoid duplicates. Realpath cycle guard and depth cap of 64. |
| Submodules / nested repos | Read `.gitmodules`. A nested `.git` directory or file is pruned unless `scan.submodules: true`. |
| Worktrees | Get the repo root from `git rev-parse --show-toplevel`. Never assume `.git` is a directory. |
| As built (M6.1) | Names that are *always* tooling (`node_modules`, `.git`, virtualenvs, caches, IDE folders, `vendor`, `migrations`) are skipped by name; names that are only *sometimes* output are skipped on evidence: `packages/` (NuGet: next to a `.sln`/`packages.config`, or holding `.nupkg`), `bin/`/`obj/`/`publish/` (next to a .NET project, or holding `Debug/`/`Release/`/DLLs), `target/` (next to a Maven/sbt/Cargo/Gradle build), `build/`/`out/`/`dist/` (unless a Python package), `env/` (only a virtualenv). Media and archives are dropped quietly. Every other skip is a `walk` degradation (`tooling_dir`, `build_output`, `excluded`, `file_too_large`, `binary`, `minified`, `symlink_dir`, `symlink_outside`, `nested_repo`, `submodule`). Extractors that glob on their own use `walker.excluded_path` (repo-relative — before M6.1 a checkout under any directory named like `.cache` or `build` lost every file). Test-file rules below are not part of M6.1. |
| Test files | One anchored rule set per language (`src/test/java/**`, `*Tests.cs`, `*.Tests/` project folders, `*.spec.ts`, `test_*.py`). A path that merely *contains* "test" is not a test. |

**Acceptance (M6.1):** fixtures for each row. A JS monorepo fixture with `packages/*` is parsed. A symlink loop terminates. Skipped files appear in the run report with their reason.

## 2. Encoding fallback (M0.4)

**Today.** Parsers call `.decode()` strictly. One CP949/EUC-KR byte raises an error, and `_parse_one` (`src/ai_discovery/pipeline.py:~599`) drops the **whole file**. Korean legacy code is a primary target, so this is High priority.

**Target.** `src/ai_discovery/core/encoding.py` (new). Its `read_source(path) -> (utf8_bytes, detected, lossy)` follows this order:
1. **BOM sniff.** UTF-8-sig, UTF-16 LE/BE.
2. **Strict UTF-8.** Tried before declared hints (changed in M0.4): valid UTF-8 is a stronger signal than a possibly stale header such as a JSP still declaring `EUC-KR` after conversion.
3. **Declared hints.** JSP `pageEncoding=` / `contentType charset=`, `<?xml encoding=?>`, `<meta charset>`, Python `coding:` cookie (in-file only; `web.config`/`.editorconfig` hints not yet used).
4. **Legacy candidates.** Configurable list, default `["cp949", "euc-kr"]`. CP949 is a superset of EUC-KR, so try it first.
5. **Last resort.** UTF-8 with `errors="replace"`, `lossy=True`.

Transcode to UTF-8 **before** handing bytes to tree-sitter, so byte offsets and line numbers stay consistent. Record `encoding` per file in `code_nodes.metadata` and count fallbacks on the scan (`degradations`, kind `encoding_fallback`/`encoding_lossy`).

**Fixtures:** CP949 C#, Java, JSP and ASPX files whose Korean comments sit inside class bodies. The Hangul must survive, and the symbols must be extracted.

Every new query string must compile under the pinned tree-sitter floor (M0.3 test). Repowise's issue #2165, where 13 of 27 queries silently failed on older grammar versions, is the cautionary tale.

## 4. Resolution rules (M1.12 edge contract + M6 follow-ups)

### 4.1 Contract (M1.12, ADR-0004)

1. **Closed origin vocabulary, with one fixed confidence per origin.** `call_edges.resolved_by` already exists (`src/ai_discovery/db.py:71`) with ad-hoc values (`index`, `exact`, `import_scope`, `receiver_type`, `interface_impl`, `short_name`, `short_name_community`, `unresolved`). Normalize it into an enum in `src/ai_discovery/graph/origins.py` (new). The canonical origin table (names and confidences) lives **only** in [ADR-0004](../adr/0004-edge-origin-vocabulary.md); this doc does not copy it. Notes per origin as used here: `global_unique` (0.50) is **excluded from flows and impact by default**; `dispatch` yields edge kind `dispatches_to` (cap, §4.4); `framework` yields `framework_binds`; `sql_regex` marks regex-fallback table edges (§7).

2. **Ambiguity means no edge.** Remove the fan-out (`_MAX_FANOUT=8` in `graph/call_graph.py:15`). When ≥2 candidates remain, write a row in `unresolved_calls` (new, M1.5) with `reason=ambiguous` and `candidate_count`.
3. **Unresolved means no edge.** Today an edge to the bare name is created at 0.5 (`call_graph.py:~196`), which surfaces as `UNRESOLVED` nodes in flows. Instead, write `unresolved_calls` with `reason=not_found|dynamic|builtin|external` (full enum in ADR-0004).
4. **`evidence_kind` column** with values `static`, `framework`, `dynamic_hint`, `scip`, `co_change`, `coverage` and `runtime` (ADR-0004). Overlays (`evidence-overlays.md`) add rows of their own kinds and **never** modify static confidence.
5. **No `NULL`-callee edges.** Slices and BFS (`ExecutionSliceBuilder`, entry linker) follow only resolved edges at or above an origin threshold. They use a depth cap and a visited set. The visited set, not PageRank, is the cycle guard.

**Acceptance:** bench precision ≥ the M0.12 baseline, and the recall delta is reported. Expect recall to drop when fan-out is removed. That is acceptable only if the rows show up in `unresolved_calls` and surface as "unknown" in impact answers (M5.2).

### 4.2 Guards on name matching (M1.12)
- **Same language only.** A JS `save()` never binds to a Java `save()`.
- **Builtin / stdlib blocklists per language.** `list.add`, `Map.get`, `String.Format`, `console.log`, `print` and similar never get a repo-wide guess. Also block **stdlib shadowing**: `import json` must not resolve to a repo file `json.py` unless it is a real relative import. Repowise logged 527 false edges from exactly this.
- **Only callable targets.** Classes count when called as constructors. Fields and constants never count.
- Separate **call** from **reference** from **type-use**. A method passed as a value is a reference, not a call.

### 4.3 Receiver typing (M6.2, M6.3)
Types come from declarations of fields, constructor parameters, method parameters, locals, and `new Foo().m()`. If two candidate types exist for one name, use no type. Builtin types are refused. Chained calls `a().b()` are typed from the declared return type of `a` (**done in M6.16** for Java/C#, with C# extension methods; decisions.md, Chained calls). **M6.2 (C#):** a receiver whose declared type is not a repo type and has no repo implementation is `external` — never a name-only guess (see `docs/architecture/decisions.md`, C# scope rules). **M6.3 (Java):** locals and parameters type receivers; receivers keep the outer type (`List`), the JPA view the element type; Spring Data interface methods are call targets; the foreign-receiver rule covers Java (decisions.md, Java scope rules). **M6.5.a (JS/TS):** relative imports (ES and CommonJS `require`) bind calls to the function defined in the named file, through barrel re-exports; queries run per grammar so TS files have call sites (decisions.md, JS/TS module rules). **M6.5.b (Vue):** SFC scripts parsed at their real offsets; template handlers and imported component tags are `framework` edges, matched by file (decisions.md, Vue single-file components).

### 4.4 Override dispatch (M6.7)
`dispatches_to` (origin `dispatch`) goes from a base or interface method to each same-signature implementation in a subtype. Exclusions:
- private methods and constructors;
- **the whole fan-out is refused if there are more than 24 implementations**, recorded as `unresolved_calls reason=dispatch_cap`.

Today `interface_impl` fires only when exactly one implementation exists; the cap generalizes that safely.

## 5. DI adapters (M6.7)

DI is the largest single source of missing edges in brownfield Spring and .NET code. Adapters live in `src/ai_discovery/extractors/di_*.py` (new) and are auto-discovered. They emit `framework_binds` with `evidence_kind=framework`.

| Stack | Bindings to read | Edge rule |
|---|---|---|
| Spring (annotations) | `@Component/@Service/@Repository/@Controller` stereotypes (also entry-point hints), `@Autowired/@Inject/@Resource` fields, constructor injection (an implicit single constructor, Lombok `@RequiredArgsConstructor`), `@Bean` factory methods, `@Qualifier`, `@Primary` | Interface → implementation edge **only if unambiguous** after the qualifier/primary rules. Otherwise `unresolved_calls reason=di_ambiguous`. |
| Spring XML | `<bean id class>`, `<property ref>`, `<constructor-arg ref>`, `<context:component-scan>` | Resolve `ref` → class. String bean ids become `dynamic_hint` evidence when only seen in `getBean("x")`. |
| ASP.NET Core | `services.AddScoped/AddTransient/AddSingleton<I,T>()`, `TryAdd*`, factory lambdas (hint only) | I → T `framework_binds` |
| Classic .NET | Unity `RegisterType<I,T>`, Autofac `RegisterType<T>().As<I>()`, `web.config` `<unity>` sections | Same as above. Assembly scanning (`RegisterAssemblyTypes`) produces hints only. |
| Angular | `@Injectable`, constructor parameter types, `providers: [{provide, useClass}]` | Token → class |

Reflection and string dispatch (`Class.forName`, `Activator.CreateInstance`, `Type.GetType`, `importlib.import_module`) produce `dynamic_hint` edges. They are shown in impact answers as "possible", and **never** followed by flow tracing.

## 7. SQL and data edges (M6.8, M6.9, M6.10)

**Today.** Regex-only (`src/ai_discovery/extractors/sql_extractor.py`). The `.sql` skip check runs on the absolute path, so a repo cloned under `/build/` loses every `.sql` file.

- **M6.8 sqlglot.** `src/ai_discovery/extractors/sql/` (new) parses DDL and DML with a per-project dialect (`tsql`, `oracle`, `mysql`, `postgres`; HANA support is **(Unverified)**). Each statement emits `reads_table` / `writes_table` edges. **Writes outrank reads in impact ranking** (`mcp-and-agents.md`).
  - SQL embedded in strings is analysed only when the literal contains a SQL verb. Interpolated table names are skipped and recorded as `dynamic_hint`.
  - A parse failure falls back to the existing regex, counted as degradation `sql_regex_fallback`.
  - The skip check uses repo-relative paths.
- **As built (M6.8).** `extractors/sql/` (`literals.py`, `parse.py`); `sql_extractor.extract_table_access`, called from the graph stage, persists `sql_table` nodes (`sql::<table>`) with `reads_table`/`writes_table` edges (origin `sql_parsed` 0.90, or `sql_regex` 0.60 on fallback). A literal counts as SQL only with a statement *shape* (`SELECT … FROM`, `INSERT INTO`, `UPDATE x SET`, `DELETE FROM`, `MERGE INTO`, `CREATE|ALTER|DROP TABLE|VIEW…`, `WITH x AS (`) and either upper-case keywords or SQL punctuation — UI strings like "Create a catalog item" are not SQL. JPQL/HQL (`@Query` without `nativeQuery = true`, `createQuery`, `@NamedQuery`) is skipped: it names entities, not tables. Only callables are callers (a class's source repeats its methods). Degradations: `sql_regex_fallback`, `sql_dynamic_table`. The dialect order comes from the source (`.NET`/brackets → tsql, backticks → mysql, `VARCHAR2`/`NUMBER(` → oracle, else postgres), not from config.
- **M6.9 MyBatis.**
  - Mapper XML `namespace` + statement `id` ↔ the Java mapper interface method (`framework_binds`).
  - `<select|insert|update|delete>` bodies go through sqlglot, with dynamic `<if>`/`<foreach>` flattened into a best-effort statement.
  - `${}` substitution is treated as dynamic and gets a hint.
  - MyBatis is prevalent in Korean enterprise Java **(Unverified, Inference)**; M0.12 and owner repos confirm.
- **M6.10 Stored procedures.**
  - Procedure nodes come from `CREATE PROCEDURE/FUNCTION`.
  - Code → procedure `calls_proc` edges come from `SqlCommand` + `CommandType.StoredProcedure`, JDBC `CallableStatement` `{call x}`, MyBatis `statementType="CALLABLE"` and `EXEC x`.
  - Procedure → table read/write comes from the body via sqlglot. Procedural coverage of T-SQL/PL-SQL in sqlglot is **(Low confidence)**, so keep a regex fallback for `INSERT INTO|UPDATE|DELETE FROM|MERGE INTO|FROM|JOIN` and mark those edges `evidence_kind=static` with origin `sql_regex`.
- Column-level lineage is Exploring.

## 8. Entry points and flow tracing (M6.12, plus the M1.12 slice rules)

**Before M6.12.** Entry points came from node type plus *substring* name hints (`cmd`, `handler`, …), which over-triggered. The flow BFS enqueued unresolved and fanned-out edges and recorded no stop reason (fixed by M1.12.b).

**As built (M6.12).** `graph/entry_points.py` scores every callable from evidence; strong = 0.8, weak = in-degree 0 (0.2), anchored name (0.2), public (0.1), fan-out (0.1); threshold 0.5. Each `EntryPoint` carries its `kind` (sets the scenario trigger type) and `evidence`. Weights, exclusions and measured precision/recall are in `docs/architecture/decisions.md` ("Entry-Point Scoring") and `benchmarks/2026-11-01-entry-points.md`. The depth-8 / 50-flow tracer below is M6.17.

**Entry-point score** (evidence-based, threshold tuned on the bench):
- framework/route/markup registration: strong; any one is sufficient;
- `main`, TCODE, scheduled job, servlet mapping, `Global.asax` events: strong;
- public visibility, in-degree 0 from production code, fan-out: weak;
- anchored name patterns (`*Controller.*`, `*Handler.handle`, `on*` markup handlers): weak.

Test, fixture and demo paths are excluded.

**Flow tracing:**
- Follow only edges whose origin passes the threshold (`global_unique` is excluded by default).
- Maximum depth 8, maximum 50 flows per entry point.
- Each flow records one **stop reason**: `leaf_no_callees` (never called "leaf", because it may be unresolved), `depth_cap`, `cycle`, `unresolved_call`, `dynamic_dispatch`, `external_boundary`, or `db_boundary`.
- Unresolved stops are visible in flow pages and in the MCP "unknowns" list.

## 9. Measurement (M6.13)
See `benchmark-protocol.md`. Each M6 item adds at least one hard-case fixture to `tests/corpus`, because the current `baseline.json` scores 1.0 nearly everywhere and can't tell good from bad. Precision is reported per language × origin. CI fails on any regression greater than the noise band recorded in the baseline.
