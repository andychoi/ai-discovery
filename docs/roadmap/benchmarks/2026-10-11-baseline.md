### Misses decomposed
- **`short_name` (name-only) is the weak origin everywhere it matters:** Java 0.70, C# 0.57. Patterns:
  - BCL/JDK/library calls linked to a same-named in-repo method — `List<T>.Add` / `RepeatedField.Add` → `OrderRepository.Add` (9 of 13 C# misses), `Validator.validate` → `PetValidator.validate`, `Object.toString` → `NamedEntity.toString`.
  - Same-named **test methods** chosen as targets — `vets.findAll()` → `PetClinicIntegrationTests.findAll`.
  - **Overloads ignored** — `getPet(Integer)` vs `getPet(String)`, `GetGenericTypeName(this object)` vs `(this Type)`.
  - Python: instance method vs same-named Flask view (`u1.follow` → `routes.follow`).
- **`external_system` in C# keys off variable names:** 11 of 26 wrong — a local named `request` (MediatR command, gRPC DTO, `HttpContext.Request`) became an "external HTTP request" edge. All `httpclient` edges were right.
- **`interface_impl`** misses: NSubstitute mock setups linked to the real implementation; an implementation from a *different project* of the same solution chosen.
- **`unresolved` C# misses** are type references (constructor parameters, fields) recorded as calls; petclinic's one miss is `owners.findById`, declared on `OwnerRepository` (the known Spring Data gap).
- **`receiver_type` was right in every sampled case** (30/30 across Java and C#).

These map directly onto M1.12 (closed origin vocabulary, no name-only fan-out to library-shadowing targets, unresolved → `unresolved_calls`, type references are not calls) and M6.2/M6.3 (overloads, generics, same-project preference).

- No pre-registered bands (first run).
- Precision graded by Claude, not by a human (owner decision); spot-check before treating as authoritative.

## 7. Verdict
Baseline recorded. The headline problems are (a) 65–79% of emitted call edges have no target, and (b) name-only resolution is wrong 30–43% of the time in Java/C#, mostly by shadowing library calls with same-named in-repo methods. Receiver-type resolution is precise. Separately, the prose path is not benchmark-ready on a local gateway (>10 h for 20 files) and had a silent zero-summary bug for repos under a `tests/` path (M0.13). M1.12's edge contract is the next lever; this file is the reference it must beat (precision ≥ these per-stratum values, recall loss explained by `unresolved_calls`).
